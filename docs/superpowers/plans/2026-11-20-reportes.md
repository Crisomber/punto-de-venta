# Reportes de Venta — Plan de Implementación

> **Para agentes:** SUB-SKILL REQUERIDA: usar superpowers:subagent-driven-development (recomendado) o superpowers:executing-plans para implementar este plan tarea por tarea. Los pasos usan sintaxis de checkbox (`- [ ]`) para seguimiento.

**Objetivo:** Darle al dueño las cuatro métricas de venta que pide la spec §6 — total vendido, platillos más vendidos, desglose por método de pago y ticket promedio — filtrables por rango de fechas, y sin que ningún otro rol pueda verlas. Ya es viable: el plan de Caja generó la entidad `Pago`, que es la fuente real de "una venta ocurrió" (una orden `CERRADA` sin pagar no es una venta todavía).

**Límite de alcance:** Este plan cubre las historias #6 y #7 completas. Se divide en dos endpoints en vez de uno solo: un endpoint de totales (monto, ticket promedio, desglose por método) y uno de ranking de platillos — las dos mitades de la historia #6 tienen una fuente de datos distinta (`Pago` directo vs. un join `Pago → Orden → OrdenItem → Platillo`) y probarlas por separado es más claro que mezclar ambas en una sola prueba de integración con muchas aserciones.

**Arquitectura:** Un nuevo paquete `reporte` con `ReporteController` (dos endpoints, uno por tarea) y sus DTOs. No se crean entidades ni migraciones nuevas — todo se calcula al vuelo sobre `Pago`/`OrdenItem`/`Platillo`, que ya existen. Patrón de autorización: `DUENO`-only, sin excepción — es la única información que la spec marca como confidencial frente a todos los demás roles.

**Stack técnico:** El mismo de siempre — Java 21, Spring Boot 3.5.x, Spring Data JPA, Spring Security, pruebas de integración con Testcontainers. Sin dependencias nuevas, sin migraciones nuevas.

**Spec:** `docs/2026-11-13-pos-restaurante-design.md` — historias de usuario #6-7, §6 "Reportes (exclusivos del dueño)". Depende de `docs/superpowers/plans/2026-11-20-caja.md` (`Pago`), ya implementado.

## Restricciones Globales

- **Una venta, para este reporte, es una fila de `Pago` — no una `Orden` en cualquier estado.** Una orden `CERRADA` pero no pagada todavía no cuenta; una orden `PAGADA` cuenta exactamente una vez (consistente con cómo Caja ya trata el momento del cobro como el evento real de venta).
- **El rango de fechas se interpreta como días calendario completos en UTC.** `desde` es inclusive desde las `00:00:00`; `hasta` es inclusive hasta el final de ese día — en código, el límite superior real que se usa en la consulta es `hasta + 1 día` a las `00:00:00`, exclusivo. Esto es consistente con que el resto del backend ya guarda todo en `Instant` sin zona horaria propia.
- **`desde` y `hasta` son obligatorios en los dos endpoints.** Ninguna historia pide un reporte "de siempre" sin filtro. Si `desde` es posterior a `hasta`, `400`.
- **Los dos endpoints son `DUENO`-only, sin excepción** — ni siquiera `CAJERO`, que es quien genera los `Pago` que el reporte lee.
- **Un rango sin ventas no es un error.** `totalVendido`/`totalEfectivo`/`totalTarjeta`/`ticketPromedio` son `0`; `cantidadCuentas` es `0`; la lista de platillos más vendidos está vacía. Nunca una división por cero.
- **El ranking de platillos cuenta todos los `OrdenItem` de las órdenes pagadas en el rango, sin importar a qué `Ticket` pertenecían** — un platillo agregado después del envío inicial a cocina también se contabiliza, igual que ya pasa con el monto del pago en Caja.
- **`ReporteController` es `@Transactional` desde la Tarea 1**, mismo motivo recurrente de `open-in-view: false` (leer `pago.getOrden()`/`item.getPlatillo()` fuera de la transacción que los cargó lanza `LazyInitializationException` en producción real).

## Puntos de Atención para Revisión

- Verificar que `totalEfectivo + totalTarjeta == totalVendido` siempre — ningún `Pago` se cuenta dos veces ni se pierde.
- Verificar el caso sin ventas en el rango elegido (ambos endpoints) — no debe lanzar excepción ni devolver `null` en ningún campo numérico.
- Verificar que una orden pagada con platillos de ambas estaciones (P1 y P2) los cuente todos en el ranking, no solo los de una.
- Confirmar que `CAJERO` —que sí puede generar pagos— no pueda leer ninguno de los dos reportes.

```java
@RestController
@RequestMapping("/api/reportes")
@Transactional
public class ReporteController {

    private final PagoRepository pagoRepository;

    public ReporteController(PagoRepository pagoRepository) {
        this.pagoRepository = pagoRepository;
    }

    @GetMapping("/ventas")
    public ReporteVentasResponse ventas(@RequestParam @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate desde,
                                         @RequestParam @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate hasta) {
        validarRango(desde, hasta);
        List<Pago> pagos = pagosEnRango(desde, hasta);

        BigDecimal totalVendido = pagos.stream().map(Pago::getMonto).reduce(BigDecimal.ZERO, BigDecimal::add);
        BigDecimal totalEfectivo = pagos.stream().filter(p -> p.getMetodo() == MetodoPago.EFECTIVO)
                .map(Pago::getMonto).reduce(BigDecimal.ZERO, BigDecimal::add);
        BigDecimal totalTarjeta = pagos.stream().filter(p -> p.getMetodo() == MetodoPago.TARJETA)
                .map(Pago::getMonto).reduce(BigDecimal.ZERO, BigDecimal::add);
        BigDecimal ticketPromedio = pagos.isEmpty() ? BigDecimal.ZERO
                : totalVendido.divide(BigDecimal.valueOf(pagos.size()), 2, RoundingMode.HALF_UP);

        return new ReporteVentasResponse(totalVendido, totalEfectivo, totalTarjeta, ticketPromedio, pagos.size());
    }

    private void validarRango(LocalDate desde, LocalDate hasta) {
        if (desde.isAfter(hasta)) {
            throw new ResponseStatusException(HttpStatus.BAD_REQUEST, "desde no puede ser posterior a hasta");
        }
    }

    private List<Pago> pagosEnRango(LocalDate desde, LocalDate hasta) {
        Instant desdeInstant = desde.atStartOfDay(ZoneOffset.UTC).toInstant();
        Instant hastaInstant = hasta.plusDays(1).atStartOfDay(ZoneOffset.UTC).toInstant();
        return pagoRepository.findByFechaGreaterThanEqualAndFechaLessThan(desdeInstant, hastaInstant);
    }

}
```

```java
@GetMapping("/platillos-mas-vendidos")
public List<PlatilloMasVendidoResponse> platillosMasVendidos(
        @RequestParam @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate desde,
        @RequestParam @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate hasta) {
    validarRango(desde, hasta);
    List<Pago> pagos = pagosEnRango(desde, hasta);
    List<UUID> ordenIds = pagos.stream().map(pago -> pago.getOrden().getId()).toList();
    if (ordenIds.isEmpty()) {
        return List.of();
    }

    List<OrdenItem> items = ordenItemRepository.findByOrden_IdIn(ordenIds);
    Map<UUID, List<OrdenItem>> porPlatillo = items.stream()
            .collect(Collectors.groupingBy(item -> item.getPlatillo().getId()));

    return porPlatillo.values().stream()
            .map(lista -> new PlatilloMasVendidoResponse(lista.get(0).getPlatillo().getId(),
                    lista.get(0).getPlatillo().getNombre(),
                    lista.stream().mapToInt(OrdenItem::getCantidad).sum()))
            .sorted(Comparator.comparingInt(PlatilloMasVendidoResponse::cantidadVendida).reversed())
            .toList();
}
```
