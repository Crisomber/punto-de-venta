# Caja — Plan de Implementación

> **Para agentes:** SUB-SKILL REQUERIDA: usar superpowers:subagent-driven-development (recomendado) o superpowers:executing-plans para implementar este plan tarea por tarea. Los pasos usan sintaxis de checkbox (`- [ ]`) para seguimiento.

**Objetivo:** Darle al cajero (Caja P1) una pantalla de cuentas cerradas pendientes de cobro, y la capacidad de cobrarlas — registrando el método de pago, marcando la orden como `PAGADA`, liberando la mesa (si la orden tenía una) y generando el recibo consolidado de Caja. Cierra el ciclo de vida de la orden: `ABIERTA → ENVIADA → CERRADA → PAGADA`, que hasta ahora se detiene en `CERRADA` (plan de Toma de Órdenes).

**Hallazgo importante — recorte de alcance frente a la historia #24 literal:** la historia #24 dice textualmente "se descuente automáticamente el inventario usado". Revisé el backend actual: **`INGREDIENTE` y `RECETA_ITEM` no existen todavía** — ninguna de las historias #3 (definir receta) ni #4 (registrar ingredientes) se ha implementado. Sin receta, no hay nada que decirle al sistema cuánto descontar de cada ingrediente por cada platillo vendido. Por eso este plan **no** incluye el descuento de inventario — lo deja explícitamente pendiente (ver Restricciones Globales y Fuera de Alcance) hasta que exista un plan de Inventario (Ingredientes + Recetas) previo. El resto de la historia #24 (marcar pagada, liberar mesa, generar el recibo) sí se cubre completo.

**Límite de alcance:** Este plan cubre las historias #22 (ver cuentas cerradas pendientes) y #23+#24 combinadas en un solo endpoint de cobro (registrar método de pago y marcar pagada son, en este modelo de datos, el mismo evento — `PAGO` se crea una sola vez, en el momento del cobro). El descuento de inventario de la historia #24 queda fuera, por la razón anterior.

**Arquitectura:** Un nuevo paquete `caja` con la entidad `Pago`, `PagoRepository`, y `CajaController`. Reutiliza `OrdenResponse`/`OrdenItemResponse` (Toma de Órdenes) tal cual, igual que `TicketController` ya hizo — no se duplica el DTO, aunque sí se duplican los helpers privados de mapeo (`toItemResponse`, etc.), siguiendo el mismo patrón ya establecido en `OrdenController` y `TicketController` en vez de extraer un util compartido que nadie pidió. Patrón de autorización: `CAJERO`-only, estricto (ni siquiera `DUENO` entra a estos endpoints, igual que `/api/ordenes/**` es `MESERO`-only sin excepción para `DUENO`).

**Stack técnico:** El mismo de siempre — Java 21, Spring Boot 3.5.x, Spring Data JPA, Spring Security, Flyway, pruebas de integración con Testcontainers. Sin dependencias nuevas.

**Spec:** `docs/2026-11-13-pos-restaurante-design.md` — historias de usuario #21-24, §8 "Modelo de datos" (`PAGO`, `ORDEN.estado = PAGADA`, `MESA.estado`). Depende de `docs/superpowers/plans/2026-11-19-backend-fundamentos.md` (`AuthenticatedUser`, roles) y `docs/superpowers/plans/2026-11-20-toma-de-ordenes.md` (`Orden`, `OrdenItem`, `Mesa`), ambos ya implementados.

## Restricciones Globales

- **El cajero se obtiene de su propio `Usuario` (consultado por id), nunca del JWT** — mismo patrón ya usado en `OrdenController.abrirOrden` y `TicketController.misTickets`.
- **El `monto` del pago se calcula siempre en el servidor**, sumando `precio_unitario * cantidad` de **todos** los `OrdenItem` de la orden (sin importar a qué `Ticket` pertenezca cada uno — un platillo agregado después del envío inicial también cuenta). El cliente nunca manda un monto; el `PagoRequest` solo trae el método de pago.
- **Solo una orden en estado `CERRADA` puede cobrarse.** `ABIERTA`/`ENVIADA` → `409` (la cuenta todavía no se cerró). `PAGADA` → también `409` (ya se cobró — no se puede cobrar dos veces), con un mensaje distinto al caso anterior para que el error sea claro, aunque el código HTTP sea el mismo.
- **`Pago` es 1 a 1 con `Orden`** — `orden_id` tiene `UNIQUE` a nivel de base de datos. El chequeo de `estado == CERRADA` ya evita un segundo cobro en el flujo normal, pero el `UNIQUE` es el respaldo real contra una condición de carrera (dos requests de cobro casi simultáneos).
- **El recibo de Caja (`ReciboResponse`) no es un `Ticket` nuevo.** Se arma en el momento, en memoria, consultando `OrdenItemRepository.findByOrden(orden)` — exactamente como ya lo documenta la spec §8 ("el recibo de Caja no es un TICKET nuevo: se arma consultando todos los ORDEN_ITEM de la orden en el momento del pago").
- **`CajaController` es `@Transactional` desde la Tarea 1**, misma razón de siempre: con `open-in-view: false`, leer `orden.getMesero()`/`orden.getMesa()`/`item.getPlatillo()` fuera de la transacción que cargó la entidad lanza `LazyInitializationException` en producción real.
- **Una orden `PARA_LLEVAR` no tiene mesa (`orden.getMesa() == null`)** — cobrarla no debe liberar ninguna mesa ni lanzar `NullPointerException`. Solo se libera la mesa cuando `orden.getMesa() != null`.
- **El descuento de inventario queda fuera de este plan**, bloqueado porque `INGREDIENTE`/`RECETA_ITEM` no existen todavía (ver Objetivo). No se simula ni se deja un `TODO` a medias en el código — simplemente no se implementa, y se documenta como pendiente real, no como decisión de negocio (a diferencia de la restricción P2 del plan de Cocina, esta es una dependencia técnica no resuelta, no una preferencia).

## Puntos de Atención para Revisión

- Verificar que el `monto` del recibo nunca pueda ser influenciado por el cliente — ni con un campo `monto` extra en el body, ni con ningún otro truco; el servidor lo recalcula siempre desde `OrdenItemRepository`.
- Verificar que cobrar una orden `PARA_LLEVAR` (sin mesa) no lance `NullPointerException` ni intente liberar una mesa inexistente.
- Verificar que un segundo intento de cobro sobre la misma orden (ya `PAGADA`) falle con `409`, no con un éxito silencioso ni con un recibo duplicado.
- Confirmar que `GET /api/caja/pendientes` no incluya órdenes `ABIERTA`, `ENVIADA` ni `PAGADA` — solo `CERRADA`.

```java
@RestController
@RequestMapping("/api/caja")
@Transactional
public class CajaController {

    private final OrdenRepository ordenRepository;
    private final OrdenItemRepository ordenItemRepository;

    public CajaController(OrdenRepository ordenRepository, OrdenItemRepository ordenItemRepository) {
        this.ordenRepository = ordenRepository;
        this.ordenItemRepository = ordenItemRepository;
    }

    @GetMapping("/pendientes")
    public List<OrdenResponse> cuentasPendientes() {
        return ordenRepository.findByEstado(EstadoOrden.CERRADA).stream()
                .map(orden -> toResponse(orden, obtenerItems(orden))).toList();
    }

    private List<OrdenItemResponse> obtenerItems(Orden orden) {
        return ordenItemRepository.findByOrden(orden).stream().map(this::toItemResponse).toList();
    }

    private OrdenItemResponse toItemResponse(OrdenItem item) {
        Set<UUID> modIds = item.getModificadores().stream().map(Modificador::getId).collect(Collectors.toSet());
        Set<String> modNombres = item.getModificadores().stream().map(Modificador::getNombre).collect(Collectors.toSet());
        return new OrdenItemResponse(item.getId(), item.getPlatillo().getId(), item.getPlatillo().getNombre(),
                item.getCantidad(), item.getPrecioUnitario(), item.getEstado(), modIds, modNombres);
    }

    private OrdenResponse toResponse(Orden orden, List<OrdenItemResponse> items) {
        return new OrdenResponse(orden.getId(),
                orden.getMesa() == null ? null : orden.getMesa().getNumero(),
                orden.getMesero().getId(), orden.getMesero().getNombre(),
                orden.getTipo(), orden.getEstado(), orden.getFechaApertura(), orden.getFechaCierre(),
                items);
    }

}
```

```java
@PostMapping("/{ordenId}/pagar")
public ReciboResponse pagar(@PathVariable UUID ordenId, @RequestBody PagoRequest request, Authentication authentication) {
    if (request.metodo() == null) {
        throw new ResponseStatusException(HttpStatus.BAD_REQUEST, "metodo requerido");
    }
    Orden orden = ordenRepository.findById(ordenId)
            .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND));
    if (orden.getEstado() != EstadoOrden.CERRADA) {
        throw new ResponseStatusException(HttpStatus.CONFLICT, "la orden no esta cerrada o ya fue pagada");
    }

    AuthenticatedUser caller = (AuthenticatedUser) authentication.getPrincipal();
    Usuario cajero = usuarioRepository.findById(caller.usuarioId())
            .orElseThrow(() -> new ResponseStatusException(HttpStatus.UNAUTHORIZED));

    List<OrdenItem> items = ordenItemRepository.findByOrden(orden);
    BigDecimal monto = items.stream()
            .map(item -> item.getPrecioUnitario().multiply(BigDecimal.valueOf(item.getCantidad())))
            .reduce(BigDecimal.ZERO, BigDecimal::add);

    Pago pago = new Pago();
    pago.setOrden(orden);
    pago.setCajero(cajero);
    pago.setMetodo(request.metodo());
    pago.setMonto(monto);
    pago.setFecha(Instant.now());
    pagoRepository.save(pago);

    orden.setEstado(EstadoOrden.PAGADA);
    ordenRepository.save(orden);

    Mesa mesa = orden.getMesa();
    if (mesa != null) {
        mesa.setEstado(EstadoMesa.LIBRE);
        mesaRepository.save(mesa);
    }

    List<OrdenItemResponse> itemResponses = items.stream().map(this::toItemResponse).toList();
    return new ReciboResponse(orden.getId(), mesa == null ? null : mesa.getNumero(),
            cajero.getId(), cajero.getNombre(), pago.getMetodo(), pago.getMonto(), pago.getFecha(), itemResponses);
}
```
